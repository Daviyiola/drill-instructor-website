# Drill Instructor Web App Migration Plan

Last updated: 2026-08-09

## Goal

Build a responsive Drill Instructor web application that preserves the identity,
workflow, and interaction patterns of the existing Felgo application while
adapting them appropriately for desktop and browser use.

The Felgo application is the behavioral and visual reference. The root
`functions/` directory is the canonical backend candidate. Firebase Realtime
Database remains the operational database for the initial migration.

## Product principles

1. Preserve product identity, not literal mobile dimensions.
   - Keep recognizable navigation, terminology, visual hierarchy, cards,
     question interactions, results, ranks, and educator workflows.
   - Adapt mobile stacks into desktop sidebars, split views, wider tables,
     dashboards, and keyboard-friendly controls where that improves usability.
   - At mobile web widths, follow the existing Felgo layouts closely.

2. Share behavior across platforms.
   - Put authorization, scoring, licensing, points, and data-shaping rules in
     Cloud Functions.
   - Keep clients responsible for presentation, local interaction state, and
     carefully bounded caching.
   - Avoid implementing Firebase path and custom-ID conventions independently
     in each client.

3. Migrate in vertical slices.
   - Each slice should include the interface, API contract, rules, loading and
     error states, responsive behavior, and verification.
   - A slice is complete only when it works against the existing Firebase
     account and data model.

4. Preserve mobile compatibility during transition.
   - Rule and schema changes must be checked against current QML reads and
     writes before deployment.
   - Use compatibility Functions or staged rules where the mobile client still
     depends on direct RTDB access.

5. Treat question content as protected application data.
   - Do not ship answer keys in the web bundle.
   - Use the server-owned drill session and grading endpoints.
   - Deliver large question images through managed storage/CDN paths.

## Visual direction

### Core palette

- Primary green: `#4B5320`
  - Replaces the Felgo primary dark olive `#414131`.
- Mist surface: `#F6F8FB`
  - Replaces the Felgo beige/gray surface `#D9D1CF`.
- Gold accent: `#E8B44B`
  - Use selectively for highlights, achievements, active status, and emphasis.
- White remains the primary content surface.
- Slate/near-black neutrals should be used for readable text and borders.

### Translation rules

- Mobile bottom/tab navigation becomes a desktop sidebar or compact top-level
  app navigation, while returning to a mobile pattern at narrow widths.
- Mobile full-screen lists can become desktop list/detail or table/card views.
- Mobile overlays become accessible dialogs, drawers, or popovers depending on
  task complexity.
- Question-taking should retain a focused, distraction-light presentation.
- Analytics should keep the Felgo metrics and meaning but use web-appropriate
  responsive charts, tables, and drill-down panels.
- Touch targets must remain generous; desktop must also support keyboard focus,
  hover feedback, and sensible tab order.

## Current technical baseline

### Web

- Next.js 16.2.11 App Router with React and TypeScript.
- Tailwind CSS v4 design tokens.
- Existing routes are a marketing site only.
- Production build currently passes.
- Firebase Web SDK and application authentication are not yet installed.

### Felgo

- Student and educator roles.
- Firebase Authentication through REST calls.
- Direct RTDB REST access plus HTTPS Cloud Functions.
- Local SQLite caches for sessions, submissions, analytics, rosters,
  assignments, bookmarks, rankings, and challenges.
- ACT and SAT question datasets are packaged in the client.
- UTME/WAEC appear in catalog/assets but are not supported by the new root
  student-drill API.

### Backend

- Root `functions/` is newer than `Drill_Instructor/functions/`.
- The root version contains browser CORS support and server-owned student drill
  endpoints.
- Root Functions test result at review time: 30 passing.
- Root Functions now have an independent install and lockfile. The current
  Firebase packages pass tests and lint. A dependency refresh removed all
  high/critical production audit findings; seven moderate upstream transitive
  advisories remain, so deployment remains gated on a dependency decision.

### Firebase

- Realtime Database remains the initial source of truth.
- The current export contains private production-like user and learning data
  and must not be committed.
- `Firebase/rtdb_rules.txt` is the deployed baseline; its compatibility and
  inheritance audit is captured in `Firebase/RULES_AUDIT.md`.
- Demo-only Firebase project and Realtime Database emulator configuration are
  checked in; the production project is deliberately not the default.
